### Saved evaluation identity

The optional `[%wcengine ...]` PGN command contains a URI-encoded JSON array:
`[profile, packageBuild, uciEngineName]`. It accompanies `[%eval]`; disabling
engine annotations removes both. Unknown or malformed identity metadata does
not invalidate the score. Older PGNs explicitly say their engine is unrecorded.
The local build comes from `localStockfishBuild.json`, which the asset sync
script updates after copying the actual engine files; installing a newer npm
package alone must not relabel the already bundled files.

This makes source differences visible. It does **not** yet isolate complete
analysis runs or change the existing depth-based replacement/review-reuse
policy. A review can still contain multiple producers; its displayed source
summary comes from the review's own evaluation map, including a frozen report.

## Performance measurements

### Returning visits

The immutable-asset change removes four network requests from the tested warm
startup. This is a request count, **not** a claimed percentage improvement in
page-load time. The document, engine assets and any previously unseen chunks may
still need the network. The cache check deliberately disables the HTTP cache so
that the browser's own freshness heuristics cannot account for the improvement.

The policy is limited to hashed JS/CSS beneath this service worker's `assets/`
path. A Range request still reaches the network and returns 206. Offline loads
retain the isolation headers needed for multithreaded Stockfish.

### Review throughput: the existing pool

Re-ran `scripts/benchmark-review-browser.cjs` against the actual Stockfish 18 Lite
single-thread WASM build. Opera Game, 33 targets, depth 18, 64MB total Hash,
Chromium reporting 18 logical cores; fresh workers in A–B–B–A order.

| Workers | Run 1 | Run 2 | Mean |
| --- | ---: | ---: | ---: |
| 1 | 16.707s | 16.248s | 16.478s |
| 4 | 8.226s | 8.107s | 8.167s |

The existing pool is **2.02× faster** on this fixture and machine, about 50% less
wall time. Every run scored all 33 targets at the requested depth. This does not
establish identical move grades, universal speedup, or low-memory-device safety.
No pool algorithm changed in this pass. The older audit's 5× result used another
game, depth and environment and must not be presented as this run's result.

### Repeated principal-variation conversion

`scripts/benchmark-pv-browser.cjs` exercises the conversion calls made for 100
updates of a five-PV panel: the Coach label, its clickable line and five Pro
lines. Every call receives a fresh array containing unchanged moves. The
result checksum remains 54,000 across six samples before and after the change.

| Conversion work only | First sample | Median of next five |
| --- | ---: | ---: |
| Before caching | 143.535ms | 138.950ms |
| With the cache | 3.830ms | 0.130ms |

These are Chromium development-module **microbenchmarks**, not React render
times, search speed, interaction latency, or an overall application speedup.
New positions and changed displayed PVs still need a replay. The cache retains
at most 128 results, keys on the full FEN and displayed moves, and freezes both
the array and its entries so a consumer cannot corrupt another view.

## Stockfish and reference-repository research

- [Stockfish 19](https://stockfishchess.org/blog/2026/stockfish-19/) was released
  on September 5. It adds native WebAssembly targets and stricter position/UCI
  validation; invalid input can terminate the engine. A migration needs explicit
  handling and tests for this failure mode.
- The app's provider,
  [nmrugg/stockfish.js](https://github.com/nmrugg/stockfish.js), still documents
  Stockfish 18. On this date `npm view stockfish version` returned `18.0.8`; the
  app's full CDN URLs pin `18.0.7`. The local lite build and the full browser build
  are different strength/download choices. The full build exceeds 100MB; making
  it every beginner's default would impose a substantial download.
- [lichess-org/stockfish-web](https://github.com/lichess-org/stockfish-web)
  includes SF19 and SF19 small-network builds, but explicitly describes its
  integration as more involved. It is an adapter/build migration, not a safe
  substitution of a version number in the current worker URLs.
- [Lichess's evaluation controller](https://github.com/lichess-org/lila/blob/master/ui/lib/src/ceval/ctrl.ts)
  throttles updates, reuses completed search effort, and unloads a worker when
  another tab starts analysis. This app already batches engine updates and
  caches finite navigation searches. Cross-tab resource ownership is a useful
  next comparison, with care to preserve intentionally running game reviews.
- [Nibbler](https://github.com/rooklift/nibbler) exposes constrained root searches,
  PV previews, arbitrary variations and Chess960. This app already has the first
  three. Chess960 remains a rules/PGN/board/engine project, not a missing switch.
- [Stockfish's UCI documentation](https://official-stockfish.github.io/docs/stockfish-wiki/UCI-Protocol-and-Stockfish-Commands.html)
  defines `searchmoves` as a restriction on root moves. Its resulting score is
  conditional on that restriction, which is why it must not overwrite a
  whole-position reading. The same documentation recommends MultiPV 1 for the
  best performance; game review already uses one PV per worker.
- [Vite's production guidance](https://vite.dev/guide/build.html) describes old
  dynamic-import filenames disappearing after deployments. The cache and dialog
  fixes above address the cached and uncached cases separately.

Decision: keep the working SF18 browser integration for now. Evaluate the 18.0.8
provider patch separately; prototype SF19 behind a distinct engine adapter and
compare download, boot time, search throughput, memory and position validity
before changing the default.

## Features worth building next

1. **Repertoire study with a due queue.** Build on the existing saved variation
   trees and line drills: chapter names, side to train, remembered attempts,
   due dates, and a short daily session. Keep imports/exports lossless. Useful
   both to a beginner learning one opening and to a tournament player reviewing
   a repertoire.
2. **Calibrated easier opponents and staged lessons.** The current lowest
   Stockfish setting is advertised around 1320 Elo, already strong for a new
   player. Measure actual playing behavior rather than assigning a smaller Elo
   label; add exercises for piece safety, mating patterns and basic endings with
   explicit success criteria.
3. **Comparable saved analysis runs.** Preserve engine version/profile, limits,
   depth, timestamp and the line reviewed. Let advanced users compare two runs
   without silently mixing their evaluations or changing a finished report.
4. **Chess960 after a rules-layer design.** Add only when castling, imports,
   exports, board input and UCI position encoding can be tested together. This
   expands serious-player coverage but is larger than the fixes above.
